# ft_transcendence — 21 Subject Points

1. **Create a complete web application**  
   The project must include a real frontend, backend, and database working together.

2. **Use Git properly**  
   Every team member must contribute. Commits should be clear, meaningful, and show a real distribution of work.

3. **Run the project with containers**  
   Use Docker, Podman, or another container solution. The whole project should start with one documented command.

4. **Support the latest stable Google Chrome**  
   The application must work correctly on the latest stable Chrome version.

5. **Keep the browser console clean**  
   There should be no JavaScript errors or warnings during normal use of the application.

6. **Add Privacy Policy and Terms of Service pages**  
   Both pages must be easy to access and contain real content related to the project. They cannot be empty or placeholders.

7. **Support multiple users at the same time**  
   Different users must be able to stay connected and use the application at the same time without conflicts, broken state, or data corruption.

8. **Build a responsive and accessible frontend**  
   The interface must work correctly across desktop, tablet, and mobile sizes and remain clear and usable.

9. **Use a styling solution**  
   Use a CSS framework or another organized styling solution such as Tailwind, Bootstrap, Material UI, Styled Components, or an equivalent solution.

10. **Protect secrets and environment variables**  
    Real secrets must stay in a local `.env` file ignored by Git. Provide an `.env.example` without real secret values.

11. **Design a clear database schema**  
    Tables or collections must have understandable relations, fields, and responsibilities.

12. **Implement secure registration and login**  
    Users must be able to sign up and log in using at least email and password. Passwords must be stored securely using proper hashing and salting.

13. **Validate user input on both sides**  
    Forms and other user input must be checked in the frontend and again in the backend.

14. **Use HTTPS for browser-to-backend communication**  
    Any request from the browser, scripts, or external APIs to the backend must use HTTPS. Internal backend container communication may stay unencrypted.

15. **Reach at least 14 module points**  
    Major modules are worth 2 points and Minor modules are worth 1 point. Only complete and demonstrable modules should be counted.

16. **Use frontend and backend frameworks if claiming the framework module**  
    A Major module is available when both sides genuinely use frameworks, for example React on the frontend and NestJS, Express, Django, or another valid framework on the backend.

17. **Implement real-time features if selected**  
    WebSocket or similar technology should provide live updates, handle connection and disconnection correctly, and broadcast data efficiently.

18. **Implement user interaction if selected**  
    The required parts are a basic chat system, user profiles, and a friends system with add/remove behavior and a visible friends list.

19. **Implement standard user management if selected**  
    Users should be able to update profile information, upload an avatar, use a default avatar when needed, manage friends, see online status, and have a profile page.

20. **Implement advanced permissions if selected**  
    The system should support user CRUD, roles such as admin, user, moderator, and different actions or views depending on the user's role.

21. **Implement advanced 3D graphics correctly if the globe is used for this module**  
    A simple rotating sphere is not enough. The 3D environment should include meaningful rendering work, smooth interaction, and good performance using a library such as Three.js or Babylon.js.
