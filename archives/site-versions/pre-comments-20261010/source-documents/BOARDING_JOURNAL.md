Au début j'imaginer un vote tous les mois pour élire le meilleur projet et une vote pour le meilleur projet all time, en faisant participer tous les campus. J'hésite entre permettre l'utilisation d'un executable en ligne pour tester les projets mais certaines contraintes m'ammènent à penser qu'il vaut mieux se contenter de screenshot et de vidéo de présentation hébergé sur youtube et intégrer dans le site pour le moment. Comment se passe chaque étape de la soummmision de projet au lauréat.

1. Les studs ont une certaine période pour soummetre une présentation de leur projet.
 - Un stud peut soummettre plusieurs projet qu'il peut faire participer à plusieurs catégories s'il le désire (exemple : best UI, best best documentation, best project), mais jamais 2 projets dans la même catégorie.
 - Pour les projets de groupes chaque studs compte pour une participation donc il ne peut pas soummetre un projet solo dans une catégorie ou il fait parti d'un projet de groupe.
 - Les projets doivent être ceux du tronc commun ou post-cursus. Mais on peut éventuellement ajouté une catégorie annexe qui ne serait pas lié aux autres "best original project" pour les projets perso.
2. Un premier tour a lieu au sein de chaque campus, tous les studs sont invité à voter dans les différents catégories. 3 votes par catégories pour tous les studs.
 - 1er : 3pts
 - 2eme : 1pt
 - 3eme : 0.5pt

3. Une fois les votes clôturé, les résultats sont révélées le lendemain (pour le suspens).

4. Chaque lauréat participera ensuite au Awards annuel ou se confronteront les projets des studs de chaque campus.
5. Les votes se passes de la même façon mais à plus grande échelle.

  - Pour son campus :

   3ème place : 0.5 pt
  - Pour un autre campus :
   1ère place : 5 pts
   2ème place : 3 pts
   3ème place : 2 pt

Apres reflexion je pense que les studs vont simplement éviter le plus possible de voter pour un autre campus mdrr. Je pense qu'empecher le vote pour quelqu'un de son campus n'est pas une si mauvaise idée.

Pour le déchiffrement, les premiers enchaînements ressemblaient trop à un diaporama. Je voulais une vraie animation, avec un message construit à partir du nombre 42. L'idée s'est précisée en plusieurs étapes : partir du binaire, passer par l'hexadécimal, faire apparaître des caractères encore chiffrés avec des lettres, des chiffres et des symboles, puis révéler « BEYOND THE CODE ». Je tenais à garder les symboles dans cette recherche.

Un prototype web séparé a été créé pour travailler ce mouvement dans le navigateur. Après des essais avec XOR 42 et une rotation sur les seules lettres, le calcul utilisé dans les essais est devenu une rotation de 42 positions sur un alphabet de 76 caractères. « BEYOND THE CODE » donne le texte chiffré `ru%43t 9xu s4tu`. Le binaire et l'hexadécimal représentent les mêmes octets chiffrés ; c'est seulement à la dernière étape que le message est réellement décodé. Le slogan reste en anglais dans les trois langues de l'interface.

Les transitions étaient encore trop brusques et reposaient au départ sur un fondu. Une transformation des formes a donc été réalisée en Canvas : les bits se regroupent vers l'hexadécimal, puis les chiffres se recomposent en caractères. Le prototype permet de jouer une connexion simulée ; le visiteur passe directement au 42 sans dévoiler la phrase. Les huit tests du moteur sont passés, et des contrôles visuels ont été faits sur ordinateur et mobile, avec les thèmes clair et sombre et le texte final exact. Cette animation web reste distincte des cadres de révélation de Figma.

J'ai ensuite demandé plusieurs exemples séparés pour comparer d'autres mouvements. On est parti de quatre essais : les rouleaux, les panneaux basculants, l'onde de déchiffrement et le terminal. Huit autres se sont ajoutés : tracé continu, profondeur, ruban, grille, prismes, orbites, iris et ligne élastique. Pour chercher quelque chose de plus fluide et dans l'esprit 42, on a aussi essayé les découpes obliques, le tissage du code et la lentille. La charte graphique a été reprise comme référence, sans considérer ces animations comme des mouvements officiels de 42.

Au début, je pensais supprimer ces exemples après comparaison. J'ai finalement décidé de tous les garder comme archive, pour montrer le parcours de recherche. La galerie permet de passer d'un essai à l'autre, de mettre en pause, de rejouer, de ralentir et d'examiner un moment précis avec un curseur. Des problèmes de raccord, d'alignement, de chevauchement et de lisibilité ont été corrigés pendant les vérifications. Les preuves et leurs limites restent dans les [notes de recherche](work/visualizations/decryption-examples/NOTES.md).

La recherche s'est ensuite concentrée sur le scanner. Le n°16 faisait deux balayages, binaire vers hexadécimal puis hexadécimal vers caractères chiffrés, avant un défilement vertical façon hacker. J'ai précisé que je voulais des changements rapides de caractères sur place, comme dans l'onde du troisième essai. Le n°17 ne reprenait pas assez cet effet ; le n°18 a retrouvé la cascade de l'onde. J'ai ensuite demandé de retirer les traits sous les lettres et de faire le déchiffrement partout en même temps, ce qui a donné le n°19.

Pour le n°20, j'ai demandé la même base avec un mouvement vertical sur toute la largeur du texte : une seule barre horizontale descend puis remonte, au lieu de deux scanners distincts. La descente transforme le binaire en hexadécimal ; la remontée révèle les caractères encore chiffrés. Le faisceau reste visible au demi-tour et change doucement de direction. Sur mobile, il traverse le bloc des deux lignes. La galerie est ainsi arrivée à vingt essais, tous conservés.
